# Engineering Workflow · 项目工程化工作流程

[English](README.md)

这是一个帮助 AI Agent 按工程流程推进项目的 Skill。核心内容和界面元数据均为英文，本页提供中文说明。

它强调：先理解问题和现状，再设计架构与规范，随后分阶段实现、验证并完成交付。工程深度应与项目规模、风险和维护周期相匹配。

## 六个阶段

1. **识别现状**：阅读项目说明、配置和已有变更，选择工作深度。
2. **梳理需求**：明确目标、范围、输入输出、约束及可验证的验收条件。
3. **设计方案**：确定使用流程、模块职责、依赖关系和数据流。
4. **规范前置**：明确代码、接口、配置及验证约定。
5. **逐步实现**：先贯通最小端到端流程，再按优先级完善功能。
6. **验证交付**：检查验收结果、同步文档，并说明已知限制。

阶段出口是 Agent 的自检标准，不意味着每一步都需要用户批准。对于已获授权且方向明确的工作，应持续推进到交付。

## 适用场景

- 新建项目、跨模块功能开发。
- 已有项目迭代、缺陷修复、重构。
- 需要长期维护的自动化、数据或内容项目。

小范围修改可合并阶段，不强制编写完整设计文档。普通问答、翻译和独立短文不套用完整流程。

## 使用方式

下载仓库，将目录保留为 `engineering-workflow`，放入所使用 Agent 支持的技能目录，并保留 `SKILL.md` 与 `agents/openai.yaml`。也可以直接把 `SKILL.md` 提供给 Agent 阅读。

对于支持按名称调用技能的 Agent，可使用：

```text
使用 $engineering-workflow，为现有项目增加 CSV 导出功能。
先检查当前实现，明确影响范围和验收条件，再实施并验证。
```

```text
使用 $engineering-workflow，开发一个小型库存管理工具。
根据实际规模设计架构，完成可运行、可验证的交付。
```

具体安装位置和发现机制由 Agent 决定。本仓库提供技能文件，不含自动安装器；元数据允许在宿主支持时自动选用技能。技能本身不依赖运行时或外部服务。

英文版保留原版六阶段流程及核心约定。原文针对作者本机 D 盘的要求改写为“遵守宿主机器的存储策略”，让其他环境也能使用；路径、临时目录和缓存由使用者按本机规则配置。此 Skill 不会自动修改系统设置。
